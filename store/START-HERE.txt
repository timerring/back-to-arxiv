准备日期：2026-11-05

1. 上传哪个文件

在 Chrome Web Store Developer Dashboard 已有扩展的 Package 页选择 Upload new package；新建草稿时选择 Add new item。上传文件为：
back-to-arxiv-0.8.0.zip

这是安装包，manifest.json 已位于 ZIP 根目录，包含构建后的脚本、界面、语言文件和图标。
back-to-arxiv-0.8.0-store-kit.zip 是包含全部材料的资料包。先解压资料包，再选取其中的安装包上传。
每个 ZIP 附带 .sha256 校验文件。

4. 隐私与审核

privacy-practices.txt：单一用途、各权限用途、远程代码和数据处理说明，可按字段粘贴。本版本保留四项必需权限与原有 alphaXiv 页面范围，新增仅在获取操作时请求的可选 https://export.arxiv.org/* 域名访问。说明包含按需查询、标题 Markdown、BibTeX 和限速时间戳。
reviewer-instructions.txt：英文审核测试步骤，包含公开测试论文地址和期望结果。
privacy-policy.html：双语隐私政策网页，默认英文，可展开简体中文。

面板与批量引用在页面内存中解析、去重和生成导出。用户点击获取并在 Chrome 授权后，才向 arXiv API 发送选定的不重复编号；粘贴的标签和完整来源网址不会发送。请求省略 Cookie 与来源网址，但 arXiv 会收到编号、IP 与普通请求头。草稿和获取的信息关闭或刷新后清空。本地存储仍是四项阅读偏好；会话存储仅保留请求限速时间戳，不保存论文编号或响应。复制及 Markdown／BibTeX 下载均由用户主动请求。按后台实时字段审阅并披露这些数据处理。

• 使用已完成开发者注册的账号填写分发范围并提交审核。选择与实际发布计划一致的审核后发布选项。

资料准备完成后，发布动作仍由开发者在后台执行。当前材料不代表已经提交或获批。

5. 本版本变化

• 0.8.0 在批量整理中按需获取标题和作者，生成带标题的 Markdown 与 BibTeX；弹窗仍只保留工作台入口。
• Chrome 在首次获取时请求可选 API 域名访问。未授权、取消或获取失败时，编号链接清单仍可导出。仅点击获取会查询，不因粘贴、编辑、语言或版本切换自动请求。
• 每批最多 50 个去重编号，所有工作台串行连接，每次请求结束后至少间隔 3 秒。单次请求超时 20 秒，响应上限 2 MB；重试只查询未完成项。编辑输入、切换版本或关闭页面取消待处理请求。
• 元数据与所选明确版本匹配。Markdown 未获取标题时保留编号；BibTeX 仅包含成功获取项，显示已获取／总数。BibTeX 由 Atom 元数据在本地生成，年份取首次提交年份。
• Markdown 可粘贴到 Obsidian，.bib 可从 Zotero“文件 → 导入”导入；不连接账号、不自动同步文献库。
• 草稿和已获取信息仅在当前标签页内存保留；后台会话存储只有限速时间戳，不保留论文编号或响应。四项必需权限与持久阅读偏好保持原值，仅增加可选 API 域名。
• 既有批量上限、原始行号、版本去重、重复与错误标记、单篇智能粘贴和键盘操作继续保留。

0.5 系列功能：

• 面板支持主动输入 alphaXiv/arXiv 论文网址、现代或旧式编号，以及带 arXiv: 前缀的编号，去除前后空白并即时预览。无效输入会禁用操作，清空后返回当前页。手动输入始终在新标签页打开。
• 面板和页面控件增加临时打开菜单，可为本次操作选择摘要、PDF 或 HTML。操作遵循所选版本偏好，保存的阅读格式保持原值。
• 复制菜单增加 Markdown：固定使用摘要页地址和 arXiv:论文编号标签，标签与链接遵循同一版本偏好。主复制按钮及原有三种格式复制继续保留。
• 输入仅保留在面板内存，关闭即清空；权限、站点范围及持久保存的四项偏好与 0.4 一致。

上传 0.8.0 时，同步更新详细介绍、截图、隐私权限理由和审核说明。

6. 本地重建

在仓库根目录运行：
npm ci
npm run check
npm run package:store

需要 Node.js 22.12.0+、zip 和 unzip；macOS 已内置后两个命令。
产物位于 release/。package:store 重新构建安装包，并组装已准备好的文案和图片。

重绘商店图片：
npm run build
npm run store:assets

图片渲染需要 Playwright Chromium（npx playwright install chromium），也可设置 CHROMIUM_EXECUTABLE_PATH 使用本机 Chrome。macOS 示例：
CHROMIUM_EXECUTABLE_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm run store:assets

界面发生变化时，先运行浏览器测试生成新面板截图，再运行：
npm run store:assets -- --refresh-captures
npm run package:store

后续上传新版本时，更新 package.json、package-lock.json 和 public/manifest.json，使版本号高于商店已上传版本，并同步文案及截图。
