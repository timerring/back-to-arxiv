BACK TO ARXIV 0.9.0 — PRIVACY TAB FILLING GUIDE
Updated from the implementation on 2026-11-06; Chrome Web Store references below.

SINGLE PURPOSE — PASTE THIS
Help users read and cite supported arXiv papers. Users can search by title or selected words, open or copy a paper from a page, link, or popup input, or organize a pasted reference list in a separate workbench. They can optionally fetch paper titles and authors from arXiv and export a title-based Markdown list or generated BibTeX. Opening supports abstract, PDF, and experimental HTML; citation export uses abstract links and the selected current/latest version. Lookup, copying, and downloads require explicit user actions.

STORAGE PERMISSION — PASTE THIS
Saves reading format, current/latest version, current/new-tab choice, language, and the floating toolbar layout in chrome.storage.local. Toolbar position and minimized state are stored separately as toolbarPosition and toolbarMinimized. Drafts, fetched metadata, and batch version choices stay in the workbench's memory and clear on close or reload. The background stores only metadataNextRequestAt, a request-pacing timestamp, in chrome.storage.session so requests remain spaced across service-worker restarts. It stores no paper identifiers, titles, authors, or response XML in session storage. No paper list or browsing-history log is stored.

ACTIVETAB PERMISSION — PASTE THIS
Reads the current tab URL when the user invokes the toolbar action or shortcut, identifies a supported paper, and opens or copies its arXiv link. It also lets the popup display the current paper identifier and destination.

CLIPBOARDWRITE PERMISSION — PASTE THIS
Writes a requested arXiv abstract/PDF/HTML/Markdown link, batch Markdown list, or generated BibTeX when the user clicks Copy. The single-paper Markdown label uses the identifier. Batch Markdown can use fetched titles with identifier fallback; BibTeX includes successfully fetched papers only. Existing clipboard contents are not read. Markdown and BibTeX downloads are explicit browser file downloads and do not require the downloads permission.

CONTEXTMENUS PERMISSION — PASTE THIS
Adds Open in arXiv to supported alphaXiv/arXiv link context menus. A selection action reads the text chosen by the user. Exact supported references open directly. Other valid titles or keywords open the search page and, with optional API access, run that search.

ALPHAXIV CONTENT-SCRIPT SITE ACCESS — PASTE IF REQUESTED
Runs on https://alphaxiv.org/* and https://www.alphaxiv.org/* to identify paper URLs, display opening/copy controls, and follow navigation between papers.

OPTIONAL ARXIV API HOST ACCESS — PASTE IF REQUESTED
optional_host_permissions declares only https://export.arxiv.org/*. Clicking Fetch paper details or Search on the results page requests this access through Chrome. With permission, launching a title search from the popup or context menu runs it immediately. Search sends the submitted title or selected words as query terms with bounded pagination options. After a grant, the background requests https://export.arxiv.org/api/query with selected unique arXiv identifiers, in batches of up to 50. Raw pasted labels and complete source URLs are not sent. Requests omit cookies and the referrer; arXiv receives identifiers and ordinary network information such as IP address and headers. The response is descriptive metadata, not executable code. Denying or revoking access leaves local parsing, deduplication, and identifier-list export available. Pasting, editing, or changing settings never starts lookup. Search and batch requests share one paced connection; the user can cancel, and retry requests only unavailable papers.

IMPLEMENTATION SCOPE
Required permissions are storage, activeTab, clipboardWrite, and contextMenus. Only the two alphaXiv hosts receive page controls. The API host is optional. Search queries and results stay in the results tab until close or reload. arXiv query text is passed to the results page in a local URL fragment, which the page immediately removes. Batch metadata stays in the active workbench until close or reload. BibTeX is generated locally from Atom metadata, using the first-submission year and selected version.

REMOTE CODE
Select: No, I am not using remote code.
Explanation: All executable JavaScript, CSS, UI text, and icons are bundled. The optional arXiv API response is parsed as metadata and rendered as text, never executed. Opening a paper is ordinary browser navigation. XML parsing and independent BibTeX parsing tools used by tests are development-only and are not runtime code loaded from a server.

DATA USAGE CATEGORIES
Review Web history for current page URLs, context-menu target URLs, and paper URLs explicitly entered by users. The selection action processes user-selected text. Search sends the submitted title or selected words to arXiv. Batch lookup sends the selected paper identifiers to arXiv and receives public descriptive metadata. Match the live dashboard fields and disclosures to these behaviors, including transient local processing; do not describe the entire extension as offline or claim that the API lookup sends no data.

DATA HANDLING / REVIEWER EXPLANATION — PASTE THIS WHERE APPLICABLE
The extension identifies requested paper references locally, including manually pasted Markdown or DOI input, without contacting a DOI resolver. Drafts, line numbers, duplicates, invalid markers, fetched metadata, and generated outputs stay in the relevant page's memory and clear on close or reload. With optional host access, Fetch sends the selected unique arXiv identifiers to the official API. Search sends the submitted title or keywords (including text selected for the context-menu action) to that API. Requests omit cookies and the referrer. arXiv handles query terms, identifiers, and ordinary network information under its own privacy practices. Paper titles and authors are displayed as text. Markdown uses fetched titles when selected, falling back to identifier labels; BibTeX includes only successfully fetched, version-matched papers. It is generated locally from metadata and uses the first-submission year. Copy and .md/.bib download require user action. Reading preferences and the floating toolbar layout are saved locally; session storage contains only metadataNextRequestAt, not identifiers or responses. The organizer's version control does not change saved preferences. Executable resources are bundled. No developer-operated collection, analytics, or advertising service is included.
