BACK TO ARXIV 0.8.0 — PRIVACY TAB FILLING GUIDE
Updated from the implementation on 2026-11-05; Chrome Web Store references below.

SINGLE PURPOSE — PASTE THIS
Help users read and cite supported arXiv papers. Users can open or copy a paper from a page, link, or popup input, or organize a pasted reference list in a separate workbench. They can optionally fetch paper titles and authors from arXiv and export a title-based Markdown list or generated BibTeX. Opening supports abstract, PDF, and experimental HTML; citation export uses abstract links and the selected current/latest version. Lookup, copying, and downloads require explicit user actions.

STORAGE PERMISSION — PASTE THIS
Saves reading format, current/latest version, current/new-tab choice, and language in chrome.storage.local. Drafts, fetched metadata, and batch version choices stay in the workbench's memory and clear on close or reload. The background stores only metadataNextRequestAt, a request-pacing timestamp, in chrome.storage.session so requests remain spaced across service-worker restarts. It stores no paper identifiers, titles, authors, or response XML in session storage. No paper list or browsing-history log is stored.

ACTIVETAB PERMISSION — PASTE THIS
Reads the current tab URL when the user invokes the toolbar action or shortcut, identifies a supported paper, and opens or copies its arXiv link. It also lets the popup display the current paper identifier and destination.

CLIPBOARDWRITE PERMISSION — PASTE THIS
Writes a requested arXiv abstract/PDF/HTML/Markdown link, batch Markdown list, or generated BibTeX when the user clicks Copy. The single-paper Markdown label uses the identifier. Batch Markdown can use fetched titles with identifier fallback; BibTeX includes successfully fetched papers only. Existing clipboard contents are not read. Markdown and BibTeX downloads are explicit browser file downloads and do not require the downloads permission.

CONTEXTMENUS PERMISSION — PASTE THIS
Adds Open in arXiv to supported alphaXiv/arXiv link context menus. The chosen link's target URL is identified locally, then opened in a new tab using the user's reading preferences.

ALPHAXIV CONTENT-SCRIPT SITE ACCESS — PASTE IF REQUESTED
Runs on https://alphaxiv.org/* and https://www.alphaxiv.org/* to identify paper URLs, display opening/copy controls, and follow navigation between papers.

OPTIONAL ARXIV API HOST ACCESS — PASTE IF REQUESTED
optional_host_permissions declares only https://export.arxiv.org/*. Clicking Fetch paper details requests this access through Chrome. After a grant, the background requests https://export.arxiv.org/api/query with selected unique arXiv identifiers, in batches of up to 50. Raw pasted labels and complete source URLs are not sent. Requests omit cookies and the referrer; arXiv receives identifiers and ordinary network information such as IP address and headers. The response is descriptive metadata, not executable code. Denying or revoking access leaves local parsing, deduplication, and identifier-list export available. Pasting, editing, or changing settings never starts lookup. All workbenches share one paced connection; the user can cancel, and retry requests only unavailable papers.

IMPLEMENTATION SCOPE
The four required permissions remain storage, activeTab, clipboardWrite, and contextMenus. AlphaXiv content-script matches are unchanged. Version 0.8 adds optional export.arxiv.org access and the session pacing timestamp; it does not add required host access or persist citation metadata. Title, author, and BibTeX data remain in the active workbench until it is closed or reloaded. BibTeX is generated locally from Atom metadata, using the first-submission year and selected version.

REMOTE CODE
Select: No, I am not using remote code.
Explanation: All executable JavaScript, CSS, UI text, and icons are bundled. The optional arXiv API response is parsed as metadata and rendered as text, never executed. Opening a paper is ordinary browser navigation. XML parsing and independent BibTeX parsing tools used by tests are development-only and are not runtime code loaded from a server.

DATA HANDLING / REVIEWER EXPLANATION — PASTE THIS WHERE APPLICABLE
The extension identifies requested paper references locally, including manually pasted Markdown or DOI input, without contacting a DOI resolver. Drafts, line numbers, duplicates, invalid markers, fetched metadata, and generated outputs stay in the relevant page's memory and clear on close or reload. Only an explicit Fetch click, after optional host access is granted, sends selected unique arXiv identifiers to arXiv's official API; pasted labels and complete source URLs are excluded. Requests omit cookies and the referrer. arXiv handles the identifiers and ordinary network information under its own privacy practices. Paper titles and authors are displayed as text. Markdown uses fetched titles when selected, falling back to identifier labels; BibTeX includes only successfully fetched, version-matched papers. It is generated locally from metadata and uses the first-submission year. Copy and .md/.bib download require user action. Four reading preferences are saved locally; session storage contains only metadataNextRequestAt, not identifiers or responses. The organizer's version control does not change saved preferences. Executable resources are bundled. No developer-operated collection, analytics, or advertising service is included.
