Back to arXiv 0.9.0 — reviewer test instructions

Access and purpose
The extension opens and copies arXiv paper links from supported alphaXiv/arXiv pages, hyperlinks, and paper URLs or identifiers entered in the popup. Testing uses public paper pages and requires Chrome 120 or later.

1. Initial state
Install and pin Back to arXiv. Open or refresh:
https://www.alphaxiv.org/abs/1706.03762v7
Expected: Open arXiv, Copy, and their menus at the lower right. Fresh defaults: English, Abstract, Current version, Open in a new tab off. The popup input starts empty and its preview follows the current page.

2. Default navigation
Click the page's Open arXiv control.
Expected current-tab destination: https://arxiv.org/abs/1706.03762v7
Return to the alphaXiv test URL. Current-page actions in the popup and shortcut use the same saved reading preferences as the page button.

3. Temporary opening formats
Keep the saved reading format at Abstract and the version at Current version. Open the arrow beside Open in the popup, then choose PDF. Expect https://arxiv.org/pdf/1706.03762v7 in the current tab. Return to the source and reopen the popup: Abstract remains saved. Repeat through the page's Open menu with HTML, expecting https://arxiv.org/html/1706.03762v7. Enable Open in a new tab and repeat: the temporary action now opens a new tab. Temporary choices use the saved version and tab preferences. Restore current-tab opening.

4. Manual paper input from another webpage
Open https://example.org and invoke the popup. Enter 1706.03762v3. Expect an immediate preview of https://arxiv.org/abs/1706.03762v3. Click Open: the paper opens in a new tab and example.org stays open, including while Open in a new tab is off. From the source tab, reopen the popup: the input is empty. Repeat input with arXiv:1706.03762v3, hep-th/9901001v2, https://www.alphaxiv.org/overview/1706.03762v3, and https://arxiv.org/pdf/1706.03762v3.pdf. Leading/trailing spaces are trimmed. Each input selects one paper; preview and copy use that paper. A temporary opening format for manual input also opens in a new tab and leaves the saved reading format unchanged.

Smart-paste cases: enter [Attention](https://arxiv.org/abs/1706.03762v3), [Attention](<https://arxiv.org/abs/1706.03762v3>), and <https://arxiv.org/abs/1706.03762v3> separately. Each selects 1706.03762v3; copy generates the clean paper URL and ignores the pasted label. Repeat with 10.48550/arXiv.1706.03762, doi:10.48550/arXiv.1706.03762, https://doi.org/10.48550/arXiv.1706.03762, and https://dx.doi.org/10.48550/arXiv.1706.03762. Each selects unversioned 1706.03762 with both Current version and Latest version. These DOIs identify the latest version; parsing does not contact a DOI resolver. A Markdown link whose destination is one of these DOI URLs is also accepted.

5. Input priority and validation
Return to https://www.alphaxiv.org/abs/1706.03762v7. Enter hep-th/9901001v2 in the popup: preview and actions target the entered paper. Replace it with a malformed reference such as arXiv:invalid: all open and copy actions are disabled. Clear the field: preview and actions return to the current page's 1706.03762v7. Close and reopen the popup after entering a valid paper: input is empty and preview follows the current page again.

Also reject: Read [paper](https://arxiv.org/abs/1706.03762), two Markdown links, [paper](https://arxiv.org/abs/1706.03762 "title"), a journal DOI such as 10.1038/example, and 10.48550/arXiv.1706.03762v3. The extension accepts one complete supported reference, not a paragraph or a versioned DOI.

6. Main Copy and copy-format menus
Click Copy on the page and Copy original link in the popup; paste each result into a local text field.
Expected: https://arxiv.org/abs/1706.03762v7
The main Copy action uses the abstract format even when PDF or HTML is the saved reading format. Choose Copy PDF link from the copy menu: expect https://arxiv.org/pdf/1706.03762v7. Choose Copy HTML link (experimental): expect https://arxiv.org/html/1706.03762v7. Repeat through the page's menu, including the abstract choice. Saved reading format stays unchanged. Escape or clicking outside closes a menu; both menus are keyboard-accessible.

7. Markdown links
Choose Copy Markdown link in the popup and on the page, then paste each result into a local text field.
Expected: [arXiv:1706.03762v7](https://arxiv.org/abs/1706.03762v7)
Select Latest version and repeat.
Expected: [arXiv:1706.03762](https://arxiv.org/abs/1706.03762)
With Current version restored, enter hep-th/9901001v2 in the popup and copy Markdown.
Expected: [arXiv:hep-th/9901001v2](https://arxiv.org/abs/hep-th/9901001v2)
The Markdown URL is always an abstract link; the label is an arXiv identifier. Clear the input.

8. Current and latest versions
Select PDF and Latest version. For the current page, preview becomes arxiv.org/pdf/1706.03762. Both the saved-format action and temporary format actions omit v7. All copied formats omit v7 as well. Enter arXiv:1706.03762v3: preview and copied links omit v3. Select Current version: the entered paper retains v3. Clear input: the current page retains v7. Latest version generates an unversioned URL locally, which arXiv resolves to its latest paper version.

9. Right-click links on another webpage
Open the public repository README:
https://github.com/timerring/back-to-arxiv
Under Supported URLs, right-click the alphaXiv paper, version 7 test link and choose Open in arXiv. With PDF and Current version selected, expect a new tab at https://arxiv.org/pdf/1706.03762v7 while the GitHub page stays open. Repeat with the arXiv paper, version 7 link. Select Latest version, then repeat: the new tab uses https://arxiv.org/pdf/1706.03762. Link actions always use a new tab. Restore Current version.

10. Experimental HTML and preference persistence
Return to the alphaXiv paper, select HTML (experimental), and enable Open in a new tab. Click Open arXiv in the popup.
Expected new-tab destination: https://arxiv.org/html/1706.03762v7
The source stays open. Reopen the popup: preferences persist. arXiv supplies HTML content; availability depends on the paper and version. Abstract and PDF are alternative reading choices.

11. Shared shortcut
On the source tab, press Alt+Shift+A on Windows/Linux or Option+Shift+A on macOS.
Expected: the paper opens using the saved format, version, and tab preference. The popup displays Chrome's assigned shortcut; use Edit or chrome://extensions/shortcuts to resolve a conflicting assignment.

12. Language and persistence
Select 简体中文. The popup, page controls, input guidance, Open/Copy menus, and right-click action use Chinese. Reopen the popup: preferences persist and paper input is empty. Select English to restore English. Follow browser uses Simplified Chinese for supported Simplified Chinese locales and English otherwise. A fresh install starts in English even on a Chinese browser.

Keyboard focus: focus Abstract and press the right arrow to select PDF. After saving, focus stays on PDF; press the right arrow again to select HTML. Changing the version or language with the keyboard likewise preserves focus after saving. If you intentionally focus the paper-input field or another control while a save is pending, focus stays where you moved it. Saving failures also reenable the preference and preserve focus when it has not moved elsewhere.

13. URL cleanup and source scope
With Current version selected, copy from https://www.alphaxiv.org/abs/1706.03762v7?utm_source=test#discussion.
Expected main Copy result: https://arxiv.org/abs/1706.03762v7
Pasting that URL in the popup produces the same result. On an unversioned source, copied URLs remain unversioned. Page controls are hidden on the alphaXiv home page. On https://example.org the popup accepts manual input and offers preferences. Supported paper links on other webpages still provide the context-menu action.

Open Batch organizer from the popup. Expect a separate extension tab; the popup remains a single-paper interface with one organizer entry. Paste this list, retaining the blank line:
https://www.alphaxiv.org/abs/1706.03762v3
- [Attention](https://arxiv.org/pdf/1706.03762v3.pdf)

1. arXiv:1706.03762v2
10.48550/arXiv.1706.03762

With Current version, expect 4 unique papers, 1 duplicate (original line 2 points to line 1), and 1 invalid reference (original line 6). Empty line 3 is ignored without changing later line numbers. The unique order is 1706.03762v3, 1706.03762v2, 1706.03762, hep-th/9901001v2. With Latest version, expect 2 unique papers, 3 duplicates, and 1 invalid reference; versioned and unversioned references to the modern paper merge. Changing this select does not alter the saved popup version preference. Replacing the invalid line with a valid paper updates the result immediately.

Copy Markdown and paste into a local text field. Download the .md file and compare its contents with the copy: both contain the unique valid papers only, each as - [arXiv:identifier](https://arxiv.org/abs/identifier), in first-occurrence order. Pasted labels are not used in output. Invalid and duplicate rows stay visible and are explicitly excluded. An all-invalid or empty list disables both export actions. A list with 501 nonblank references, or input over 100,000 characters, rejects the whole batch and disables export instead of silently truncating it. Blank lines do not count toward the 500-reference limit.

Switch the saved language in the popup and check the open workbench follows it while retaining its input and chosen batch version. Clear resets the draft and results. Reload the organizer: its draft is empty and its starting version follows the saved preference. Close and reopen likewise clears the draft. Before Fetch is clicked, the batch workspace does not query metadata. It never saves drafts. Version 0.8 adds only optional export.arxiv.org host access for on-demand retrieval; the required permissions remain unchanged.

15. Optional citation metadata and exports
Use a fresh Chrome test profile for the native optional-permission checks. In the organizer, paste:
1706.03762v1
1706.03762v7

Before clicking Fetch paper details, expect identifier Markdown to remain available with no API lookup or host-permission prompt. Click Fetch and deny the Chrome prompt: expect a clear access message, no metadata, and working local Markdown export. Click Fetch again and approve only https://export.arxiv.org/*: expect titles and authors, a fetched/total count of 2/2, title-based Markdown, and BibTeX copy/download actions. Requests use only selected identifiers; pasted labels and complete source URLs are not included. Chrome's native host prompt is not exercised by the headless suite and must be checked here.

Toggle Use titles in Markdown. The preview and copied/downloaded .md content switch between titles and identifier labels without a new metadata request. Copy Markdown and paste into an Obsidian note, or add the downloaded .md file to a test vault. Link targets retain v1/v7 under Current version. Switch to Latest version: the list merges to one unversioned identifier, old version-specific metadata is not attached, and retrieval needs a new explicit Fetch click. The returned latest metadata is used with an unversioned exported URL.

Inspect Copy BibTeX and Download .bib. Both contain only successfully fetched, unique, version-matched papers. The year for Attention Is All You Need is its first-submission year, 2017. Title, authors, selected eprint, and abstract URL must agree with the preview. The BibTeX is generated from Atom metadata, not copied from arXiv's separate BibTeX page. In a temporary Zotero library, use File → Import and choose the downloaded .bib; inspect the imported title, authors, year, and URL. This is a file import, not an account connection or library sync.

If metadata is missing or a request fails, the original Markdown list keeps identifier fallback for those papers. BibTeX explicitly includes fetched papers only; the coverage count shows the subset. Fetch unavailable details retries only missing entries. Cancel stops pending retrieval while retaining completed metadata. Editing input, changing version, or closing/reloading the workbench also cancels pending work; responses from the old selection must not populate the new one. Larger lists use sequential batches of at most 50 identifiers with at least three seconds after each request; individual requests time out after 20 seconds and reject responses over 2 MB.

Remove export.arxiv.org access in Chrome's extension site-access settings, then reload the workbench and paste a paper again. Local export must work before retrieval. A new Fetch requires optional access again; denying it leaves the local workflow available. For revocation during a longer retrieval, later requests must stop at the permission check. Closing/reloading clears the draft and metadata. Four reading preferences remain stored; chrome.storage.session contains only metadataNextRequestAt, not identifiers or XML.

Automated coverage uses an isolated staged copy of the build with the API host granted so headless Chrome can test the real service worker and intercepted Atom responses. The production package declares that host only in optional_host_permissions. Permission denial is covered separately; the native prompt and manual revocation steps above remain reviewer checks.

16. Move or minimize the page toolbar
On an alphaXiv paper, drag its handle and release it over an empty area of the page. It should stay there without opening a paper. Reload, navigate to another paper, and resize the window. The toolbar should remain visible. Click Minimize toolbar on the page and verify only one arXiv button remains. Drag it again, then click it to open the paper using the saved preferences. Right-click the minimized button to expand. Check the equivalent Minimize floating toolbar and Reset position controls in the popup. A reset returns the toolbar to its default lower-right position.

17. Search titles and selected text
Remove the optional API permission first. In the popup, enter “attention transformers” and choose Search arXiv. The results tab should initially show your query and prompt for a Search click. Deny the Chrome permission prompt, then click Search again and grant it. Results show title, authors and year, with Abstract, PDF and HTML links. Use Next and Previous where available and choose any format to open the corresponding arXiv paper in another tab. Refresh or close the search tab and verify the query and results clear. With permission granted, select a title on a webpage and invoke Find selected text on arXiv. Search should start directly. Repeat with the exact selected identifier 1706.03762v7 to open that paper using the saved reading format. Edit or cancel an in-flight search and verify the old results do not replace the new input.

18. Finish
Restore English, Abstract, Current version, and current-tab opening if desired. Refresh existing alphaXiv tabs after reloading or updating the extension. Upgrading retains existing preferences.

Previous release (0.8.0)
The batch organizer retrieves titles and authors only on request, after optional API-host access is granted. It exports title-based Markdown with identifier fallback and generated BibTeX for fetched papers only. Progress, cancellation, retry, and exact-version matching protect the existing local workflow. Single-paper controls and the popup organizer entry remain available.

Implementation notes
The required permissions remain storage, activeTab, clipboardWrite, and contextMenus. AlphaXiv content-script matches remain unchanged. optional_host_permissions adds only https://export.arxiv.org/*. The background accepts batch lookups from batch.html and search from search.html, checks host access, and performs GET requests to the fixed official API with cookies and referrer omitted. All workbenches share one paced connection; only metadataNextRequestAt is kept in chrome.storage.session across worker restarts. Paper identifiers and responses are not stored there. Reading preferences, toolbarPosition and toolbarMinimized use chrome.storage.local. Drafts, metadata, and batch-version choices stay in the workbench memory. Parsing, deduplication, and export generation are local, while Fetch sends selected identifiers and Search sends the submitted query to arXiv, which receives ordinary request headers and IP information. DOI parsing does not contact a resolver. All executable code and assets are bundled; API responses are metadata, not remote code.
